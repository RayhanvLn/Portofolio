# Editing guide

Almost everything you will want to change lives in **one file: `src/data/portfolio.ts`**.
Visual tokens live in `src/app/globals.css`, motion settings in `src/animations/config.ts`.

Placeholder copy is written in CAPS (`YOUR NAME`) or starts with "Replace", so you can search for it.
Nothing in the data file is a real achievement, client or company.

---

## 1. Profile information
`src/data/portfolio.ts` → `profile`

| Field | Shown in |
|---|---|
| `name` | Navigation, preloader, hero heading (screen readers), page titles, footer |
| `shortName` | Reserved for a compact mark; not currently rendered |
| `role` | Navigation, hero metadata, preloader, `/about` title |
| `location` | Hero metadata, footer, contact page |
| `timezone` | Live clock in the footer and on the contact page. IANA name, e.g. `Europe/Berlin` |
| `email` | Footer, contact page, mobile menu |
| `availability` | Navigation status (desktop), footer, contact page |

Page `<title>` and description: `seo` at the top of the same object.

## 2. Hero
`portfolio.hero`
- `titleLines: ['Your', 'Name']` — line 1 sits **behind** the subject, line 2 **in front** (orange). Both lines
  share one size, measured from the real letters so the longest line always fits between the side margins
  (`src/components/Hero/useHeroTitleFit.ts`). Largest allowed size: `--title-cap` in `Hero.module.css` (`.stage`).
- `mode: 'cutout'` uses the transparent portrait between the two lines (default). `mode: 'backdrop'` uses a
  normal full-bleed photo instead (see `profile.heroBackdrop`).
- `intro`, `cta`, `secondaryCta`, `scrollLabel` — the copy along the bottom.
- `showObject` — show/hide the 3D object (cut-out mode only).
- Hero entrance (photo wipe, name letters, copy): one quick timeline. On page load it starts the moment the logo
  window appears and ends as the window fills the screen (`maskZoom.heroIntro` in `src/config/pageTransition.ts`);
  after navigating from another page it lasts `introAfterSweep` seconds.

## 3. Hero logo
The logo sits centred at the top of the home hero, above the first name line, aligned with the menu toggle. It is
drawn from the same file as the transition logo (`profile.logo`) as a CSS mask, so it takes the page's text colour.
Size: `--brand-w` in `src/components/Hero/Hero.module.css` (`.brand`).

## 3b. Hero image
1. Export your cut-out as WebP with transparency: desktop 3000 × 4000, mobile 1800 × 2400.
2. Either overwrite `public/transparent/hero/hero-desktop.webp` and `hero-mobile.webp`,
   or change `images.heroCutoutDesktop` / `images.heroCutoutMobile` at the top of `portfolio.ts`.
3. If your aspect ratio is not 3:4, update the numbers in `profile.heroImage` / `profile.heroMobileImage`
   and the `aspect-ratio` of `.subjectFrame` in `src/components/Hero/Hero.module.css`.
4. Photo size on phones/tablets: `--subject-max` in `Hero.module.css` (mobile `.stage`, default `120vw`). Above
   `100vw` the left and right edges of the photo run off the screen; lower it if your shoulders/arms get cut.

The subject uses `object-fit: contain` anchored to the bottom, so nothing is cropped.

## 4. About text and images
**About page opening** (`src/components/AboutIntro/`): built from `profile.name`, `profile.role`,
`profile.location` and the first `about.bio` paragraph. The first word of the name is shown one line wide
(primary), the other names and the role sit underneath (secondary; the role in the accent style).
Sizes: `AboutIntro.module.css` → `.first` (upper bound, auto-fitted), `.second` (second row).

- Disciplines (the big interactive words), bio, facts, CTA: `portfolio.about`.
- **Main portrait:** `profile.portrait` → file `images.about01` (`public/images/about/about-01.webp`, 2400 × 3000).
- **Second, overlapping image:** `about.images[0]` → `images.about02`.
- **Floating objects:** `about.objects` → `images.object01..03` (transparent WebP).
- Experience timeline on `/about`: `portfolio.experience`.
- Skills timeline (home + `/about`): `portfolio.skills`. The `id` (`'01'`) is the large number.

## 5. Projects
`portfolio.projects` — currently generated by `makeProject(n)` for four placeholders. To use real projects,
replace `projects: [1, 2, 3, 4].map(makeProject)` with explicit objects:

```ts
projects: [
  {
    id: '01',
    slug: 'aurora-site',            // URL: /projects/aurora-site
    title: 'Aurora',
    year: '2025',
    category: 'WebGL site',
    role: 'Design and development',
    tools: ['Next.js', 'Three.js', 'GSAP'],
    description: 'One or two sentences for cards and the case-study lead.',
    cover: { src: '/images/projects/aurora/cover.webp', alt: 'Aurora home screen', width: 2560, height: 1440 },
    gallery: [
      { src: '/images/projects/aurora/detail-01.webp', alt: 'Scroll scene', width: 2400, height: 1600 },
    ],
    liveUrl: 'https://example.com', // optional — adds a "Visit live site" button
  },
],
```
Any number of projects works: the horizontal rail, project index, case-study pages (`generateStaticParams`)
and "Next project" links all derive from this array.

## 5b. Work page header (/projects)
Content: **`src/data/workPage.ts`** — `label`, `titleLines` (one per line; each line steps further right; wrap
words in `*asterisks*` for the accent style), optional `intro`. The project count is automatic.
Look: `src/components/WorkIntro/WorkIntro.module.css` (`.title` size upper bound, `.line:nth-child(n)` indents).
The dark project list card: `src/app/projects/page.module.css` (`--card-r` corner radius).
Project title size in the list: `src/components/ProjectList/ProjectList.module.css` → `.title`.

## 5c. Case study pages (/projects/…)
Labels ("Category", "Year", "Role", "Tools", "Visit live site", "Next project"): **`src/data/caseStudy.ts`**.
Title size follows the title length automatically (≤ 12 / ≤ 22 / longer characters); the three sizes are in
`src/app/projects/[slug]/page.module.css` → `.titleWrap[data-length=…]` and `.nextTitle[data-length=…]`.

**Overview** ("About the *project*", title in `caseStudy.ts` → `overviewTitle`): shows `description`. Its size follows
its length — ≤ 160 characters a large statement, ≤ 360 a large paragraph, longer a comfortable reading paragraph
(sizes: `.descWrap[data-length=…]` in `page.module.css`). Separate paragraphs with a blank line (`\n\n`) inside the
text. On the home-page project cards the description is cut to three lines. The `body` field is no longer shown
(optional — you can delete it from your projects).

**Gallery** (the detail views): framed cards in two staggered columns, the caption in a notch bottom-right
(= the image's `alt` text + its number in the accent colour). Click opens the image full size (arrow keys step
through). Labels ("Gallery", "views", "Close", …): add them to `caseStudy.ts` to change them — anything not in that file uses the defaults in `src/lib/caseStudyLabels.ts`. Look: `src/components/ProjectGallery/ProjectGallery.module.css`
— `--stagger` (how far the second column starts lower), `--pad` (space around the image), `--notch-h` (caption height).

## 6. Project images
Project covers and gallery images are always shown **whole** — frames take each image's own proportions from
the width/height numbers in `img(...)`. If you export a new size, update those two numbers to match the file.
- Covers: `public/images/projects/project-0N/cover.webp` (2560 × 1440), set by `images.projectCover(n)`.
- Details: `.../detail-01.webp`, `detail-02.webp` (2400 × 1600), set by `images.projectDetail(n, d)`.
- With explicit project objects (above), just write the paths into `cover` and `gallery`.
The gallery caption is each image's `alt`.

## 6b. Academic career (home page, under the statement)
Content: **`src/data/academic.ts`** — `titleLines` (wrap words in `*asterisks*` for the accent style), `image`
(photo next to the title; file `public/images/academic/academic.webp`, portrait 4:5, e.g. 1600 × 2000 px) and
`stats`. Each stat has a `label` and either a `value` (number that counts up; `decimals` shows e.g. 3 + .89) or

Look: `src/components/AcademicCareer/AcademicCareer.module.css`.

## 6b. Skills ("hall of fame" grid)
Tools: `skills` in `portfolio.ts` — each entry is a category (`title`) and gets its own column on desktop (its own block
on phones), in the order of the list; its `labels` are the tools (one card each, with a lettered badge, numbered 01, 02… in the notch); `description` shows on the orange panel when you hover a tool. For real logos and/or a
hover photo, give a category `tools: [{ name: 'React', icon: '/images/skills/react.svg', photo: '/images/skills/react-photo.webp' }, …]`
(files in `public/images/skills/`). Paragraph beside the title: `intro` in **`src/data/skillsSection.ts`**.
Section title: the `title` prop in `src/app/page.tsx` / `src/app/about/page.tsx` — the last line gets the orange accent style.
Look: `Skills.module.css` (columns, offset, card size, hover panel).

## 6c. Experience (About page)
Roles: `experience` in `portfolio.ts` (`period`, `role`, `organisation`, `note`). A period containing "Now" gets a pulsing
"Current" badge; the "2024 — Now" range and the (03) count are worked out from the roles.
Photos: one per role, in order — overwrite `public/images/experience/experience-01.webp`, `-02`, `-03`… (portrait 4:5,
recommended 1600 × 2000). Or give a role its own `image: { src, alt, width, height }`.
Colour per role: warm tones in order (`TONES` at the top of `src/components/Experience/Experience.tsx`), or `tone: '#hex'` on a role.
Look: `Experience.module.css` (photo size `.sticky` width, timeline, cards on phones).

## 7. Lifestyle images — "Off screen" on the About page
Photos: `lifestyle` array in `portfolio.ts` (also used as `collage.items`). Each photo is one card in the fan;
add or remove entries freely (5–9 cards look best). Cards are portrait 2:3, so portrait photos work best
(e.g. 1080 × 1620); for a landscape photo set `focus: '50% 30%'` (horizontal %, vertical %) to choose what stays in view.
`caption` + `meta` appear on a card when it is lifted (hover / tap). `color: true` keeps a card in colour;
the others are grayscale until lifted.
Title and the small "after hours" tag (`sticker`, '' hides it): **`src/data/offScreen.ts`**. Cards only lift once the fan has finished opening.
Look and motion: `src/components/LifestyleStrip/` — card size `--card-w` in the `.module.css`; fan shape
(spread, tilt, arc, lift) in `fanPose()` in `LifestyleStrip.tsx`.

## 9. Colours
`src/app/globals.css`, top of the file:
- Palette: `--c-dark` `#111112`, `--c-accent` `#FF8000`, `--c-paper` `#F1F0E9`, `--c-gray` `#777777`.
- Dark scene values in `:root`; light scene values in `html[data-scene='light']`.
  `--muted` is #777 nudged lighter/darker per scene to meet WCAG AA contrast for small text.
- The `@property` blocks register the scene colours so they animate between dark and light — if you add a new
  scene colour, register it there too and add it to the `transition` list in `:root`.
- The 3D object's orange/paper are constants at the top of `src/components/ThreeScene/ThreeCanvas.tsx`.
- Browser UI colour: `themeColor` in `src/app/layout.tsx`.

**Menu toggle** (`src/components/Navigation/`): a single button at the top right opens the full-screen menu
(Home + the `navigation` links from `portfolio.ts`, plus status, email and socials). Button size and distance from
the edge: `--toggle-size` / `--toggle-offset` in `globals.css` (the home-hero logo lines up with it). Button colours
switch automatically between light (on dark sections) and dark (on light sections). Menu look:
`Navigation.module.css` — link size `.menuList font-size` (upper bound; on phones and tablets it is fitted so the longest label fills ~74% of the width — change `fill` in `Navigation.tsx`). Menu colours (dark stage, light type, orange hover and current-page line, slightly lighter footer band — the opposite of the orange page transition) are variables at the top of `.menu`: `--menu-bg`, `--menu-ink`, `--menu-band`, `--menu-hover` (letters on hover), `--menu-current` / `--menu-mark` (current page and its line). Toggle colours while the menu is open: `.header[data-open='true']`.

Which sections are dark or light: the `theme` prop on each `<Scene>` (see `src/app/page.tsx` and the other pages).

## 10. Typography
- Font: `src/app/layout.tsx` loads **Archivo** (variable, with a width axis) via `next/font/google`.
  Display type uses it expanded (`font-stretch: 125%`, weight 850); body text uses normal width.
- To change the family, swap the import (keep `variable: '--font-archivo'` or update `--font-sans` in
  `globals.css`). If the new font has no width axis, remove `axes: ['wdth']` — the `font-stretch` and
  `'wdth'` settings will simply be ignored.
- Display sizes are `clamp()` values in each component's `.module.css` (e.g. `.title` in `Hero.module.css`).
  Shared values: line-height `0.82`, letter-spacing `-0.05em`, uppercase.

## 11. Animation settings
`src/animations/config.ts` — one place for the feel of the site:

| Setting | Effect |
|---|---|
| `stagger.*` | Delay between characters, words, lines, curtain columns |
| `depth.*` | Hero pointer parallax per layer (0.15 / 0.35 / 0.6 / 1) |
| `pointer.heroMaxOffset`, `heroRotation` | How far hero layers move / subject tilts |
| `pointer.magneticStrength` | Pull of magnetic buttons |
| `pointer.cursorLerp`, `cursorDotLerp` | Cursor smoothing (lower = smoother) |
| `scroll.lerp` | Lenis smoothness (0.07 very smooth, 0.15 snappy) |
| `scroll.velocitySkewMax`, `velocitySkewFactor`, `velocityDecay` | Momentum lean and how fast it settles |
| `reveal.start`, `imageStartScale`, `maskStops` | When reveals fire; image reveal 100% → 70% → 0% and scale 1.15 → 1 |
| `preloader.steps`, `minStepTime`, `maxWait` | Counter steps and pacing |
| `blockReveal.cover` / `hold` / `reveal` / `stagger` | Accent block reveal: block grows over a line, pause, slides away; delay between lines |
| `blockReveal.startRatio` | How far into the viewport a block-revealed text must be before it plays (0.88 = 88%) |

**Block reveal on any text.** Blocks are measured in the element's own coordinates (so they stay aligned inside sections that scale on scroll) and leave room for glyph ink; text inside `[data-block-skip]` is ignored. Wrap it in `<BlockReveal>` (`src/components/BlockReveal/BlockReveal.tsx`):

```tsx
<BlockReveal as="p" className={styles.intro} delay={0.2}>{text}</BlockReveal>
```
Props: `as` (tag), `delay`, `trigger="load"` (play when the page appears instead of on scroll),
`color` (block colour, default the accent), `mode="box"` (one block for the whole element — buttons).
It works on paragraphs, links, lists and multi-column grids (each column gets its own blocks).

Easing names: `src/animations/easings.ts` (CSS twins: `--ease-out`, `--ease-in-out` in `globals.css`).
Dark/light cross-fade length: `--scene-duration` in `globals.css`.
Reusable animations: `textAnimations.ts`, `imageAnimations.ts`, `scrollAnimations.ts`, `pageTransitions.ts`.

## 12. Page transition (logo)
Everything is in **`src/config/pageTransition.ts`** (durations in milliseconds):

| What | Setting |
|---|---|
| Background colour of the overlay | `background` (default `var(--c-accent)`; exposed to CSS as `--transition-bg`) |
| Logo file | `src/data/portfolio.ts` → `images.logo` / `profile.logo` (shared with the home hero) |
| Logo size (px) per screen | `logo.width.mobile` / `.tablet` / `.desktop` (breakpoints 640px and 1024px) |
| Logo colour on dark backgrounds | `logo.filter: 'invert(1)'` turns a black logo white |
| Overlay direction | `direction`: `'up'` (default), `'down'`, `'left'`, `'right'` |
| Overlay easing | `easing` (CSS easing, default `cubic-bezier(0.76, 0, 0.24, 1)`) |
| Logo / new content easing | `logoEasing` |
| Timing of each step | `durations` (content out, overlay in, logo in, hold, logo out, overlay out, content in) |
| New content slide distance | `contentShift` (px) |
| Page-load logo | `introAnimation` — full version on the first visit of a session (`logoIn`, `hold`), shorter on reloads (`repeatLogoIn`, `repeatHold`). Runs in pure CSS from the first paint, so the logo shows even before JavaScript is ready. `intro: 'counter'` brings back the 00→100% preloader |
| Changing page (navigation) | `navigation`: `'logoZoom'` (default — the orange logo grows from where you clicked until the screen is orange, then the dark logo opens onto the new page like the page load) or `'sweep'` (the earlier panel) |
| Growing orange logo | `logoCover.duration` (340 ms: tiny dot → full orange, timing measured from the reference), `.origin` (`'center'` like the reference, or `'click'`), `.size` (size multiplier on the measured growth curve), `.logoDelay` (pause on orange before the dark logo), `.menuWait` (clicked in the menu: pause before the orange logo starts, default 0; the menu stays open and closes once the new page is in), `.revealDuration` (zoom that opens the new page) |
| How the site opens (load / reload) | `loadReveal`: `'maskZoom'` (default — the logo becomes a window onto the page and zooms open) or `'sweep'` (the panel sweeps away like between pages) |
| Logo-window zoom | `maskZoom.duration` (first visit) / `.repeatDuration` (reloads), `.easing`, `.pageScale` (page settles from this size, `1` = off), `.readyAt` (when the hero entrance starts, `0` = as soon as the window appears), `.heroIntro` (part of the zoom the hero entrance is squeezed into), `.fadeOut` |
| Point the window opens from | `maskZoom.focus` (0–1 of the logo's width/height) — must be on a **solid** part of the logo; `maskZoom.solidRadius` = half the thickness there (fraction of the logo width) |
| Page entrance length after a normal page sweep | `introAfterSweep` (seconds) |
| Text at the bottom of the load screen | `loadLabel.text` (`''` hides it; default = your name + "Portfolio"), `loadLabel.color` |
| Reduced motion | `reducedMotion` (short cross-fades, no movement) |
| Safety nets | `imageWaitMs`, `navigationTimeoutMs` |

**Replacing the logo:** overwrite `public/assets/logo.svg`, or change `images.logo` and `profile.logo.aspectRatio`
(width ÷ height of the artwork) in `src/data/portfolio.ts` — the page transition and the home hero both use it. Tip: crop the SVG's canvas tightly around the
artwork (the provided logo was trimmed from an A4 page; the untouched original is `public/assets/logo-original.svg`).

How it works: markup in `src/components/PageTransition/TransitionOverlay.tsx` (+ `.module.css`), sequence in
`src/lib/pageTransitionEngine.ts`, orchestration with routing in `src/components/PageTransition/TransitionProvider.tsx`.
Every internal link that uses `TransitionLink` (navigation, mobile menu, footer, project cards, buttons) runs it.
The logo shows on every page load; the longer intro plays once per browser session (`sessionStorage` key `pf:intro`), reloads use the shorter timing.

**Refresh always opens at the top (hero):** the browser's scroll memory is switched off in the boot script in
`src/app/layout.tsx` (also on `pagehide`) and the provider scrolls to the top before the reveal; after the intro it is
switched back on, so Back/Forward inside the site keep their position. A URL with `#section` still lands on that section.

**Navigation (logoZoom):** `coverWithLogo()` in the engine grows a full-screen layer in the accent colour, masked to
the logo, from a tiny dot in the centre of the screen until it covers everything (sizes per moment measured from the
reference video, scaled to the screen width); the panel then
takes over, the dark logo assembles, and the new page opens through it (`revealThroughLogo()`). Links inside an element
with `data-transition-solid` (the menu): the menu stays open, the orange logo grows on top of the dark menu
(after `logoCover.menuWait`, default 0), and the menu closes only after the transition has finished. Back/Forward
also open through the logo.

**Logo window (page load):** after the logo appears, the panel gets a CSS mask with the logo cut out of it,
so the logo turns into a window onto the page; the window then grows from `maskZoom.focus` until it fills the
screen (`revealThroughLogo()` in the engine). Navigations between pages keep the sweep. If you replace the logo,
pick a new `focus` in its thickest part — otherwise the zoom opens from an empty spot and the screen only clears
at the very end. Browsers without CSS mask support, and visitors with reduced motion, get the normal reveal.

## 13. 3D object
Procedural by default. To use your own: add `public/models/hero-object.glb`, set `model.enabled: true`.
WebGL renders at high quality ≥ 900px, lighter below, pauses off-screen, and falls back to a static SVG
without WebGL, with reduced motion, or on any WebGL error.

## 14. Testing tips
- **See the intro again:** it shows once per browser session. Open a new private window, or run
  `sessionStorage.removeItem('pf:intro')` in the console and reload.
- **Reduced motion:** DevTools → Rendering → "Emulate CSS prefers-reduced-motion: reduce".
- **Touch / mobile:** DevTools device toolbar, then reload (pointer type is detected on load).
- **Placeholders:** `python scripts/generate-placeholders.py` recreates any missing placeholder.
